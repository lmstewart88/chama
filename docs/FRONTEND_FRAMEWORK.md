# Config and environment

`config.ts` reads Vite env variables (names match `.env.example`). Keep the network settings in this one file so a redeploy is one change.

```ts
export const config = {
  rpcUrl: import.meta.env.VITE_RPC_URL ?? "https://soroban-testnet.stellar.org",
  networkPassphrase: import.meta.env.VITE_NETWORK_PASSPHRASE ?? "Test SDF Network ; September 2015",
  contractId: import.meta.env.VITE_CHAMA_CONTRACT_ID as string,
  usdcId: import.meta.env.VITE_USDC_CONTRACT_ID as string,
  explorerTx: (hash: string) => `https://stellar.expert/explorer/testnet/tx/${hash}`,
};
```

Demo secrets (`VITE_DEMO_SECRET_*`) are testnet only. They are visible in the browser bundle, so they must never be reused on mainnet and never committed.

# Amount helpers (`format.ts`)

Amounts are `bigint` in 7-decimal base units (500 USDC = `5_000_000_000n`). Convert in one place.

```ts
const DECIMALS = 7;
const ONE = 10n ** BigInt(DECIMALS);

export const toBase = (usdc: string): bigint => {
  const [whole, frac = ""] = usdc.split(".");
  return BigInt(whole || "0") * ONE + BigInt((frac + "0".repeat(DECIMALS)).slice(0, DECIMALS));
};

export const fromBase = (v: bigint): string => {
  const neg = v < 0n;
  const a = neg ? -v : v;
  const frac = (a % ONE).toString().padStart(DECIMALS, "0").replace(/0+$/, "");
  return `${neg ? "-" : ""}${a / ONE}${frac ? "." + frac : ""}`;
};
```

Never use `number` for amounts, and remember `JSON.stringify` cannot serialise `bigint`; convert to strings before logging or storing.

# The data layer (`chama.ts`)

One function per contract function in `docs/INTERFACE.md`. Each has a live switch, so slices flip from mock to live one at a time.

```ts
export type Role = "admin" | "verifier" | "recipient" | "amara" | "baraka" | "chidi";

// Flip each to true when the backend lead has committed that slice's bindings.
const LIVE = {
  getState: false, getContribution: false, contribute: false,
  getMilestone: false, approveMilestone: false,
  getRemaining: false, spend: false, setCaps: false,
  rejectMilestone: false, refund: false, getRefundable: false,
};

export type ActionResult = { hash?: string };

export async function contribute(role: Role, amountUsdc: string): Promise<ActionResult> {
  const amount = toBase(amountUsdc);
  if (!LIVE.contribute) return mock.contribute(role, amount);
  const client = clientFor(role);                       // builds the generated Client for that role
  const tx = await client.contribute({ from: roles[role].publicKey, amount });
  const sent = await tx.signAndSend();
  return { hash: extractHash(sent) };                   // adapt to the result shape of your bindings
}

export async function getState() {
  if (!LIVE.getState) return mock.getState();
  const tx = await clientFor("admin").get_state();      // read-only: simulation, no signature
  return tx.result;
}
```

Functions to implement (same names as the contract, camel-cased): `getState`, `getContribution`, `contribute`, `getMilestone`, `approveMilestone`, `rejectMilestone`, `setCaps`, `getRemaining`, `spend`, `refund`, `getRefundable`.

# Signing and roles (`roles.ts`, `clientFor`)

- A role switcher in the header sets the acting role. Each role has a public key and, in demo mode, a secret from env.
- `clientFor(role)` creates the generated `Client` with the contract ID, passphrase, RPC URL, the role's public key and a signer for that keypair. The SDK exposes a keypair signer for this (look for `basicNodeSigner` in the SDK's contract module).
- Real wallet upgrade: replace the signer with the wallet's `signTransaction`, and use the connected address as `publicKey`. Keep the role switcher for the demo run, because one wallet extension acts as one account at a time.

# Errors and the Blocked state (`errors.ts`)

Contract errors surface as messages like `Error(Contract, #N)`. Keep a table that mirrors the contract's error enum (`NotInitialized, BadConfig, WrongStatus, ZeroAmount, Overshoot, NotInOrder, CapExceeded, NotApproved, AlreadyRefunded, NothingToRefund, CapsTooLarge, SupplierNotApproved`). The backend lead confirms the numbers at Gate 1 (22:30).

```ts
const ERRORS: Record<number, string> = {
  // fill the numbers from the contract's error enum
};

export function explain(e: unknown): { blocked: boolean; message: string } {
  const text = String((e as Error)?.message ?? e);
  const num = text.match(/Error\(Contract, #(\d+)\)/)?.[1];
  const name = num ? ERRORS[Number(num)] : undefined;
  if (name === "CapExceeded" || text.includes("CapExceeded")) {
    return { blocked: true, message: "Blocked by the contract: this spend is over the category cap." };
  }
  return { blocked: false, message: name ?? "Something went wrong. Details below." };
}
```

The Blocked banner shows category, cap, already spent and attempted amount, read from `getRemaining` and the form values.

# Reading state

- Poll `getState` and the views every 4 to 6 seconds, and refetch immediately after any successful action.
- Reads are simulations and need no signature.
- Show a small "last updated" time so the room can see it is live.

# Styling conventions

- CSS variables for colour, spacing and type in `styles.css`. One accent colour for primary actions, green for success, red for Blocked.
- Large type for amounts and status; the demo is read from a distance.
- Always label units ("USDC") and use whole-USDC formatting.
- Buttons are disabled with a visible reason when the action is invalid for the current status or role.
- Do not rely on colour alone for Blocked: include the word and an icon.
